## 目的
`MyPhysicalEngine/src` ディレクトリのソースコードを正確に解析し、プロジェクトのドキュメント（`MyPhysicalEngine/docs/overview.html` および `MyPhysicalEngine/docs/details.html`）を最新の状態に同期・更新すること。


## ドキュメントの定義と役割

1. **全体概要 (`MyPhysicalEngine/docs/overview.html`)**:
   - ターゲット: プロジェクトの全体像を把握したいユーザー向け。
   - 内容: プロジェクトの目的、主要コンポーネントの役割、全体アーキテクチャ、技術スタック、主要なデータフロー。
   - 制約: 個別の関数仕様には踏み込まず、抽象度の高い記述に留めること。

2. **詳細実装 (`MyPhysicalEngine/docs/details.html`)**:
   - ターゲット: 実装内容を理解・修正したい開発者向け。
   - 内容: クラス構造、各クラスのメンバ変数・メソッドの仕様（引数、戻り値、例外）、主要なアルゴリズムの詳細、データ構造の定義。
   - 制約: ソースコードと1対1で対応する正確性を最優先すること。

## 実行手順

1. **ソーススキャン**:
   - `src` 内のファイルを再帰的にリストアップする。
   - 特に重要なコアロジック（エンジン、ソルバー、メインコントローラ等）を含むファイルを優先的に特定する。
2. **解析と分類**:
   - 各ファイルを読み取り、情報を「概要」と「詳細」に分類する。
   - 依存関係（どのクラスがどこを呼び出しているか）を把握する。
3. **ドキュメントの更新（完全再構成）**:
   - **重要**: 既存のドキュメントを「追記」するのではなく、現在のソースコードを正として内容を**完全に書き換えて更新**せよ。
   - `docs/overview.html` および `docs/details.html` を更新する。
4. **整合性チェック**:
   - 更新後のドキュメントとソースコードに矛盾（引数の型違い、存在しないメソッドの記述など）がないか最終確認を行う。

## ガイドライン

- **言語**: すべて日本語。

- **HTML/CSS**:
   - セマンティックなHTMLタグを使用すること。
   - `details.html` では、クラスや関数を整理するためのテーブルや、論理的な見出し構造を適用すること。
   - 基本的なCSS（視認性を高めるためのマージン、フォントサイズ、コードブロックの装飾）を含めること。
- **正確性**: ソースコード内の型情報（`int`, `std::vector` 等）や、`const` 修飾の有無も正確に反映させること。

- **更新のトリガー**: `MyPhysicalEngine/src` に構造的な変更（新クラスの追加、APIの変更、主要アルゴリズムの書き換え）があった際は、このスキルを呼び出して同期を行うこと。
